rsync

Должна быть установлена на всех машинах.

В rsync всегда сначала указываем источник, а потом место назначения, т.е. сначала что копируем, а потом куда копируем.
Всегда используйте параметр -nv перед прогоном. rsync может натворить огромную головную боль, если что-то не так сделать.

Завершающий слеш "/"

Источник без завершающего слеша скопирует сам каталог /path/dir в удаленный каталог /dest_dir:
~]$ rsync -a /path/dir user@host:dest_dir

Путь к каталогу источнику с косой чертой в конце скопирует не сам каталог /path/dir, а все содержимое в удаленный каталог /dest_dir:
~]$ rsync -a /path/dir/ user@host:dest_dir

Небольшая инструкция по синхронизации

  1. Синхронизируем локальный каталог с удаленным сервером:
    ~]$ rsync -a -e "ssh -p 7967" html/ user@host:html/

    Примечание: -e "ssh -p 7967" указывает коннектиться по определенному порту.

  2. На удаленной машине синхронизируем каталоги:
    ~]$ rsync -a html/ /var/www/html/

Исключить каталог из операции переноса

~]$ rsync -a -e "ssh -p 7967" --exclude 'res/header' html/ user@host:html/

Команда scp

scp — копирует файлы между хостами в Сети. Работает подобно команде cp.

Примеры:

  • Файл с удаленного хоста к себе в текущую директорию —
    ~]$ scp user@host:path_file path_copy_past

  • Каталог с удаленного хоста через другой порт —
    ~]$ scp -r -P 2871 user@host:path_file path_copy_past

Внимание: для scp порт указывается с большой "P".

Инструкция по настройке сервера

Инструкция универсальна и адаптирована для семейств RHEL/CentOS/AlmaLinux и Debian/Ubuntu.

1. Настройка записей DNS

Заходим в личный кабинет на сайте, где у вас зарегистрирован домен.

Нужно в запись А добавить ip-адрес сервера. Для your_domain.com и для www.your_domain.com. Для IPv6 — AAAA-запись.

Важно: DNS-записи должны быть настроены ДО получения SSL-сертификата, так как процесс проверки права на домен требует доступности вашего домена.

2. Создаем пользователя с правами sudo

Используем VNC на сайте хостера.

  • ~]# useradd new_username — добавляем пользователя. (для Debian adduser)
  • ~]# passwd new_username — задаем ему пароль.
  • ~]# usermod -aG wheel new_username — добавляем пользователя в группу wheel. (В Debian: установить apt install sudo. Добавить в группу sudo.)

Выходим из сессии root и заходим под новым пользователем через терминал. VNC хостера больше не нужен.

3. Настройка SSH

Внимание. Для генерации ключей-SSH в Windows 11, смотрите: Генерация ключей-ssh в терминале Windows

3.1 Генерация ключа и копирование открытого ключа на сервер

  • ~]$ ssh-keygen — создаём пару ключей на станции.
  • ~]$ ssh-copy-id user@host — отправляем публичный ключ на удалённый сервер.

Если ssh-copy-id недоступен, скопируйте ~/.ssh/id_rsa.pub в ~/.ssh/authorized_keys на сервере.

Внимание: перед отключением паролей проверьте подключение по ключу в новой сессии.

3.2 Настройка файла /etc/ssh/sshd_config

Откройте файл конфигурации и внесите изменения:

~]# nano /etc/ssh/sshd_config

  • Отключить авторизацию по паролю — PasswordAuthentication no
  • Запретить вход по root — PermitRootLogin no
  • Сменить порт — Port 2222

⚠️ Для того чтобы изменения вступили в силу, необходимо перезагрузить SSH-сервер. Команда перезагрузки приведена в пункте 3.6 — её следует выполнять только после завершения всех предыдущих настроек. Если применить перезагрузку до открытия нового порта в firewall и MAC, вы потеряете доступ к серверу.

3.3 Разрешить системе обязательного доступа (SELinux / AppArmor) использовать нестандартный порт

SELinux (CentOS/RHEL) и AppArmor (Debian/Ubuntu) — системы обязательного контроля доступа (MAC — Mandatory Access Control). Они ограничивают процессы, в том числе могут блокировать использование нестандартных портов.

3.4 Открытие порта в межсетевом экране (firewall)

3.5 Права на ключи

Если ключ создан командой ssh-keygen, нужные права будут установлены автоматически.

  • ~]$ chmod 700 ~/.ssh
  • ~]$ chmod 600 ~/.ssh/*

3.6 Применение конфигурации и проверка

  • Перезагрузить конфигурацию SSH-сервера — ~]# systemctl reload sshd
  • Подключиться по новому порту — ~]$ ssh -p 2222 user@host (вместо ip-адреса можно указывать доменное имя, если домен уже подключен).

💡 Не закрывайте текущую SSH-сессию, пока не убедитесь, что подключение по новому порту работает. Если что-то пойдёт не так, вы сможете исправить ошибку в открытой сессии.

4. Установка и запуск веб-сервера

Выберите веб-сервер для установки: Apache или Nginx.

  • Перейти на официальный сайт apache.org
  • Перейти на официальный сайт nginx.org

4.1 Установка Apache

  • ~]# dnf install httpd — устанавливает Apache (пакет httpd).
  • ~]# systemctl enable httpd --now — включает Apache и добавляет его в автозапуск.

4.2 Установка Nginx

  • ~]# dnf module list nginx — вывести список модулей, которые содержит Nginx. Прим.: поток по умолчанию обозначен "[d]".
  • ~]# dnf install nginx — устанавливает Nginx.
  • ~]# systemctl enable nginx --now — включает Nginx и добавляет его в автозапуск.
  • ~]$ systemctl status nginx.service — проверяем статус службы.

4.3 Открытие портов в firewall

Для работы веб-сервера откройте порты 80 (HTTP) и 443 (HTTPS):

  • ~]# firewall-cmd --list-all — убеждаемся, что по умолчанию отсутствует разрешение на доступ по 80 порту.
  • ~]# firewall-cmd --zone=public --add-service=http --permanent — добавляем 80-й порт в виде сервиса http.

    Порт 80 ассоциирован с сервисом http в firewalld. Подробней читай в официальной документации firewalld: Open a Port or Service

  • ~]# firewall-cmd --zone=public --add-service=https --permanent — открывает порт 443 (HTTPS).
  • ~]# firewall-cmd --reload — применяет изменения в firewall.
  • ~]# firewall-cmd --list-all — проверяем, что порт открыт.

Примечание: в системе AlmaLinux 8, при установке веб-сервера Apache, порты автоматически добавились в открытые. Добавлять ничего не надо, нужно только проверить конфигурацию зоны, чтобы убедиться, что порты открыты.

Готово. Проверьте работу сервера, введя в браузере IP-адрес или доменное имя.

Проверить доступность:

~]$ curl -I http://YOUR_SERVER_IP

4.4 Конфигурация по умолчанию

Конфигурационный файл — /etc/nginx/nginx.conf. В нём веб-сервер настроен на работу на 80 порту, и нацелен на каталог контента в /usr/share/nginx/html/

5. Получение и настройка SSL-сертификата Let's Encrypt

  • Документация Let's Encrypt
  • Документация certbot

Инструкция исходит из анализа, который представлен в моём посте О сертификатах Let's Encrypt.

5.1 Установка Certbot

Certbot — это официальный клиент для получения и управления сертификатами Let's Encrypt.

Установите EPEL-репозиторий и Certbot:

sudo dnf install -y epel-release
sudo dnf install -y certbot python3-certbot-nginx   # для Nginx
# или
sudo dnf install -y certbot python3-certbot-apache  # для Apache

5.2 Автоматическая настройка для Apache

Делаем бекап. Переименовываем конфиг /etc/httpd/conf.d/ssl.conf — этот файл конфигурации создается автоматически в AlmaLinux 8, при установке httpd. В нём подключается сертификат /etc/pki/tls/certs/localhost.crt для локальной разработки.

sudo mv /etc/httpd/conf.d/ssl.conf /etc/httpd/conf.d/ssl.conf.bak

Создаем виртуальный хост:

sudo vim /etc/httpd/conf.d/linuxgik.ru.conf

<VirtualHost *:80>
    ServerName linuxgik.ru
    ServerAlias www.linuxgik.ru
    DocumentRoot /var/www/html

    ErrorLog /var/log/httpd/linuxgik.ru-error.log
    CustomLog /var/log/httpd/linuxgik.ru-access.log combined

    <Directory "/var/www/html">
        Options Indexes FollowSymLinks
        AllowOverride All
        Require all granted
    </Directory>
</VirtualHost>

Проверяем синтаксис:

sudo apachectl configtest

Перезагружаем:

sudo systemctl reload httpd

Проверяем что виртуальный хост работает:

curl -I http://linuxgik.ru

5.3 Получение сертификата

Для Apache:

sudo certbot --apache

Для Nginx (нужно настроить виртуальный хост):

sudo certbot --nginx

Для nginx я пока что не делал сам, поэтому только предполагаю, что так.

5.4 Настройка автоматического продления

Проверить работу автоматического обновления:

sudo certbot renew --dry-run

6. Рекомендации по безопасности и эксплуатации

  • Оставьте одну рабочую сессию при тестировании SSH-изменений
  • Проверьте security group провайдера, если сервер в облаке
  • Рассмотрите установку fail2ban для защиты от brute-force атак
  • Сделайте резервную копию конфигураций: sudo cp /etc/ssh/sshd_config /etc/ssh/sshd_config.bak
  • Настройте мониторинг срока действия SSL-сертификатов
  • Регулярно обновляйте систему и установленные пакеты: sudo dnf update
