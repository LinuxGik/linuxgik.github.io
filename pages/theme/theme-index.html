Структура каталогов и файлов

Все страницы сайта хранятся в каталоге pages/. При этом блог и его посты хранятся в каталоге _posts/ 

.
├── _config.yml      настройки сайта
├── _layouts/        макеты: default.html, post.html, theme.html
├── _posts/          посты (markdown): ГГГГ-ММ-ДД-имя.md
├── assets/
│   ├── css/         main.css подключает остальные файлы через @import
│   └── js/          copycode.js
├── pages/           страницы (html), по разделам
│   ├── theme/       документация этой темы
│   └── windows/     раздел «Windows»
├── index.html       главная страница (без макета)
├── CNAME            домен сайта
└── Gemfile          зависимости для локальной сборки

Имена _layouts и _posts должны быть точными. При опечатке в имени каталога Jekyll ничего не сообщает и просто не видит файлы.

Сайт разделен на разделы. Раздел делится на подразделы. Любой подраздел так же может делиться на дополнительные подразделы, и так по цепочке по мере надобности.

Переход по разделам осуществляется через главное меню сайта. Главное меню сайта отображается на любой странице сайта.

Разделы сайта

Сайт разделен на разделы. Имя каждого раздела отображается в главном меню сайта

В структуре каталогов, у каждого раздела свой каталог в pages/

Каталог раздела содержит главную страницу, которая подключается к главному меню сайта.

Страницы раздела

Все страницы раздела находятся в каталоге своего раздела.

Конфигурация: _config.yml

title: LinuxGik
url: https://linuxgik.ru
lang: ru
permalink: /:year/:month/:day/:title/
ПараметрНазначение
titleназвание сайта: идёт в <title> и в подвал сайта
urlадрес сайта
langязык, попадает в атрибут lang страницы
permalinkформат адресов постов: /2026/10/30/rsync/

Внимание: смена permalink меняет адреса всех постов. Ссылки, прописанные вручную (например, на главной), придётся поправить.

После правки _config.yml локальный сервер нужно перезапустить.

Макеты

Макеты лежат в _layouts/. Страница выбирает макет переменной layout в front matter.

МакетНаследуетЧто выводит
default — каркас страницы: <head> (заголовок вкладки, описание, main.css), меню, <main> с содержимым, подвал сайта
post default статья: заголовок h1 из title, дата, теги, текст поста. Если в front matter есть page, внизу ссылка на страницу-выжимку
theme default страница темы и разделов: заголовок h1 из pagesH1, текст страницы. Если есть post, внизу ссылка на пост

Главная страница index.html макета не использует, потому что у неё нет front matter.

Правила для макетов

  • В макете обязательно должна быть строка {% raw %}{{ content }}{% endraw %}. Без неё страница выводится пустой.
  • Макет-наследник начинается с front matter layout: default. Его содержимое подставляется на место {% raw %}{{ content }}{% endraw %} родителя.
  • <header> и <footer> в default стоят прямо в <body> и относятся к сайту. Внутри <article> они относятся к статье. В CSS различайте их: body > footer и article > footer.
  • Адреса внутри макетов пишите через фильтр {% raw %}{{ '/путь/' | relative_url }}{% endraw %}.

Front matter

Front matter — блок YAML между двумя строками --- в самом начале файла. Jekyll обрабатывает файл (Liquid, макет) только если такой блок есть. Без него файл копируется в _site/ как есть.

Переменные из front matter доступны в шаблонах как page.имя.

Внимание: в файле с front matter Liquid обрабатывается и в теле. Чтобы показать {% raw %}{{ page.title }}{% endraw %} как текст, оборачивайте его в {% raw %}...{% endraw %}.

Связь поста и страницы

Пост хранит полный разбор, страница — выжимку. Они ссылаются друг на друга через переменные page (в посте) и post (на странице). Значение — URL от корня сайта.

Front matter поста

Файл лежит в _posts/ и называется ГГГГ-ММ-ДД-имя.md.

ПеременнаяОбязательнаНазначение
layoutдазначение post
titleдазаголовок поста, выводится как h1 и в заголовке вкладки. Если есть двоеточие, берите в кавычки
dateнетдата, по умолчанию берётся из имени файла
tagsнетсписок тегов: [rsync, ssh]
descriptionдакраткое содержание для <meta name="description">
pageнетURL страницы-выжимки. Не задаётся, пока страницы нет: иначе макет выведет ссылку на несуществующую страницу
 
---
layout: post
title: "Основы rsync: синхронизация каталога"
date: 2026-10-30
tags: [rsync, ssh, деплой]
description: "Краткое содержание поста."
page: /pages/rsync/
---

В description не используйте двойной дефис --: Jekyll заменит его на тире.

Front matter страницы

Файл лежит в pages/, в каталоге своего раздела.

ПеременнаяОбязательнаНазначение

Что идёт на страницу

Команды, подводные камни и одна строка «зачем». Объяснения, варианты и разбор ошибок остаются в посте.

Относительные пути вида pages/имя.html без начального слеша ломаются на вложенных страницах, не используйте их.

Оформление команд

  • На страницах: команда в <code> с приглашением ~]$ (обычный пользователь) или ~]# (root). Несколько строк — в <pre><code> без приглашения.
  • В постах: блоки кода с указанием языка (bash, powershell, apache), без приглашения, чтобы команды копировались целиком.
  • Отличия систем: отдельные блоки с подписью «AlmaLinux 8» и «Debian». Непроверенное помечается явно.
  • Условные обозначения: your_domain.com, your_username, host, порт SSH 2222.
