Устройство двух коллекций: garden (заметки сада, статусы seed, budding, evergreen) и til (короткие ответы). Статус реализации: пока ничего из описанного не создано, это проект.

1. Конфигурация: _config.yml

Коллекции

_config.yml

collections:
  garden:
    output: true
    permalink: /garden/:slug/
  til:
    output: true
    permalink: /til/:year/:month/:day/:slug/
  • output: true — для каждой заметки создаётся своя страница.
  • Имя коллекции — имя каталога без подчёркивания: garden → _garden/.
  • :slug — имя файла без расширения и без даты. :year, :month, :day берутся из даты в имени файла.
  • У сада адрес без даты, у TIL с датой.
  • Коллекции входят в ядро Jekyll и работают на GitHub Pages без плагинов.
  • В RSS основных постов заметки не попадают: фид собирается из site.posts (если RSS будет подключён).
  • После правки _config.yml локальный сервер перезапускается.

Значения по умолчанию

_config.yml

defaults:
  - scope:
      path: ""
      type: garden
    values:
      layout: garden
      status: seed
  - scope:
      path: ""
      type: til
    values:
      layout: til
  • type — имя коллекции.
  • Макет задаётся здесь, поэтому в заметках layout не пишется.
  • Статус seed подставляется автоматически. Заметка без status не попала бы ни в одну группу индекса.

3. Front matter

Заметка сада

Файл _garden/html-article-count.md.

---
title: Сколько article может быть на странице?
status: seed                # seed | budding | evergreen
til: html-article-count     # slug связанной TIL-заметки
---

Вопрос: ...
ПеременнаяОбязательнаЗначение
titleдазаголовок заметки
statusнетseed, budding или evergreen. По умолчанию seed
tilнетslug связанной TIL-заметки
topicsэтап 3список тем: [html] или [html, css]
raised_inэтап 4список slug заметок, из которых вырос вопрос
updatedнетдата последнего дополнения (предложено, в исходной задумке нет)

Значения status описывают этап: seed — вопрос зафиксирован, budding — идёт расследование, evergreen — ответ найден.

Минимальный front matter при включённых значениях по умолчанию:

---
title: Сколько article может быть на странице?
---

TIL-заметка

Файл _til/2026-10-29-html-article-count.md.

---
title: Сколько article может быть на странице?
date: 2026-10-29
garden: html-article-count   # slug заметки сада
---

Лимита нет. article должен быть самодостаточной композицией — всё.

4. Макеты

_layouts/til.html: ссылка в сад

{% if page.garden %}
<a href="{{ site.baseurl }}/garden/{{ page.garden }}/">Подробности в саду →</a>
{% endif %}

_layouts/garden.html: статус и ссылка на TIL

Адрес TIL содержит дату, поэтому его нельзя собрать из одного slug. TIL ищется по своему полю garden. Slug заметки сада вычисляется из page.url. 

<span>{{ page.status }}</span>

{% if page.status == "evergreen" %}
  {% assign my_slug = page.url | remove: "/garden/" | remove: "/" %}
  {% assign short = site.til | where: "garden", my_slug | first %}
  {% if short %}
    <a href="{{ short.url | relative_url }}">Короткий ответ →</a>
  {% endif %}
{% endif %}

Поле til в заметке сада при такой схеме необязательно: связь строится по garden у TIL.

6. Темы (этап 3)

  • Одна коллекция плюс поле topics. Коллекции на каждую тему не заводятся.
  • topics — массив. Фильтр where понимает массивы: where: "topics", "html" найдёт заметку, даже если тем у неё несколько.
  • Список тем хранится в _data/topics.yml: slug латиницей (для фильтров и адресов), name для показа.

_data/topics.yml

- slug: html
  name: HTML
- slug: css
  name: CSS
- slug: javascript
  name: JavaScript
- slug: linux-kernel
  name: Ядро Linux

Индекс сада по темам

{% for topic in site.data.topics %}
  {% assign notes = site.garden | where: "topics", topic.slug %}
  {% if notes.size == 0 %}{% continue %}{% endif %}

  <h2>{{ topic.name }}</h2>

  {% assign seeds = notes | where: "status", "seed" %}
  {% assign buds  = notes | where: "status", "budding" %}
  {% assign trees = notes | where: "status", "evergreen" %}

  <ul>
    {% for n in seeds %}<li>🌱 <a href="{{ n.url | relative_url }}">{{ n.title }}</a></li>{% endfor %}
    {% for n in buds %}<li>🌿 <a href="{{ n.url | relative_url }}">{{ n.title }}</a></li>{% endfor %}
    {% for n in trees %}<li>🌲 <a href="{{ n.url | relative_url }}">{{ n.title }}</a></li>{% endfor %}
  </ul>
{% endfor %}

Страницы тем

Для каждой темы создаётся страница-заглушка и используется общий макет topic.

topics/html.md

---
layout: topic
topic: html
permalink: /topics/html/
---

_layouts/topic.html

{% assign notes = site.garden | where: "topics", page.topic %}
{% assign tils  = site.til    | where: "topics", page.topic %}
  • Тема в адрес заметки не входит. Адрес остаётся /garden/:slug/, тему можно менять правкой front matter.
  • Заметка с темой, которой нет в topics.yml, в индекс по темам не попадает. Такие заметки можно выводить отдельным списком в конце индекса либо искать вручную по topics: [.

7. Связь «вырос из» (этап 4)

Поле raised_in связывает заметку с теми, из которых вырос вопрос. Не зависит от topics.

---
title: В какой тег заключать статью — article или section?
topics: [html]
raised_in: [html-article-count]
---

_layouts/garden.html: «выросло из»

{% if page.raised_in %}
<p>
  {% for p in page.raised_in %}
    {% assign purl = "/garden/" | append: p | append: "/" %}
    {% assign parent = site.garden | where: "url", purl | first %}
    {% if parent %}🌱 из «<a href="{{ parent.url | relative_url }}">{{ parent.title }}</a>»{% endif %}
  {% endfor %}
</p>
{% endif %}

_layouts/garden.html: «отсюда выросли»

Считается автоматически по полю raised_in у других заметок.

{% assign my_slug = page.url | remove: "/garden/" | remove: "/" %}
{% for n in site.garden %}
  {% if n.raised_in contains my_slug %}
    🌿 отсюда выросло: <a href="{{ n.url | relative_url }}">{{ n.title }}</a>
  {% endif %}
{% endfor %}
  • Slug вычисляется из page.url, родитель ищется через where: "url", ....
  • Запись where: "raised_in", page.slug при пустом page.slug молча даёт пустой список. Это самый коварный вид ошибки.
  • Граф связей: в шаблоне digital-garden-jekyll-template его рисует include notes_graph.html.

8. Что проверить перед внедрением

ЧтоПочему
{{ page.slug }} у заметок коллекций В исходных заметках утверждалось, что поля нет. Это не подтверждено, по моему знанию Jekyll записывает slug в данные из имени файла. Проверить одной строкой на тестовой заметке, локально и на GitHub
:slug в permalink коллекции GitHub Pages собирает на Jekyll 3.10, локально 4.4.1. Сверить адрес заметки в обоих местах
Фильтр where по массивам, тег continue Должны работать в обеих версиях, проверить на примере
Адрес этой страницы Выводится как каталог: /pages/theme/digital-garden/ (причина — permalink в конфиге)
